### 機能（`ProductFeature`）

プロダクトを構成する**「何（What）」の単位**。「機能仕様」とも呼ぶ。

## 何か
- プロダクトを構成する具体的な要素。
- プロダクトヒエラルキー上で、コンポーネントの下、サブ機能の上に位置する。

## サブ機能の階層化

機能は 2 階層までネスト可能。サブ機能の階層化には主に 2 パターン:

### パターン A: カテゴリ的にまとめる
ある機能カテゴリの中に、具体的な機能が並ぶ。

```
機能:ログイン機能
  └─ サブ機能:メールアドレスログイン
  └─ サブ機能:Google ログイン
  └─ サブ機能:SAML 認証
```

### パターン B: ベース機能 ＋ 派生仕様
ベースとなる機能があり、その派生仕様としてサブ機能が並ぶ。

```
機能:AI チャット機能
  └─ サブ機能:マルチモーダル対応
  └─ サブ機能:human-in-the-loop
```

## 「共通化」（同じ機能を別の場所にも置く）

異なる階層位置に**根本的には同じ機能**を置きたいときは、機能名を入力すると
既存機能がサジェストされる。共通化すると、ノートやタイムラインが共用化される。
GraphQL では `master` / `references` で表現される。

## 主な紐付け先

| 相手 | 紐付け方 |
|---|---|
| タスク（`Task`） | `Task.productFeatures` ↔ `ProductFeature.tasks` の多対多。タスク作成・更新時に `productFeatureIds` で指定 |
| エピック（`Epic`） | `Epic.productFeatures` で多対多。エピック作成・更新時に `productFeatureIds` で直接紐付け可能 |
| 目標（`Objective`） | 2 経路で紐付け可能: (1) プロダクトヒエラルキー上の「目標カラム」 (2) 機能の詳細サイドバー「目標・顧客価値」セクション |

## 廃止
- バージョン履歴の `ancestor` / `descendant` は廃止（ノートのバージョン機能で置換済み）。
  共通化の `master` / `references` とは別物なので混同しない。
