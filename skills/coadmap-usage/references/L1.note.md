### ノート（`Note`）

サイドバーの「ノート」。組織・プロダクト・プロジェクト・タスクなど、**ほぼ全てのリソースにぶら下げられる文書**。

## 何か
- 議事録・仕様メモ・設計ログなど、構造化されていない情報の置き場。
- 必ず 1 つの所有者にぶら下がる（`ownerableType` / `ownerableId`）。
- 所有者に指定できる種別: アカウント / 組織 / プロジェクト / プロダクト / 機能 / ノート /
  コンポーネント / リリース / エピック / タスク / 目標 / ナレッジ / イニシアチブ / アウトカム /
  ロードマップナレッジ / リポジトリ / 顧客の企業。
- 顧客の企業が持つのは、企業のコンテキストノート（企業に 1 つ。人が書く正本）だけ。Yata の経路からは読むだけで、
  作成・更新・本文の操作は 403。見られるのは企業を見られる人で、ほかの人には見つからない（404）。まだ誰も開いていない企業では無い。
- 会議体の会議の議事録のノートは、Yata の経路からは変えられない（直接の書き込みも変更案も 403。読めない議事録のノートは 404）。

## 公開範囲

`accessibility` は `public` / `internal` / `private` の 3 段。省略すると Rails 側の既定（`internal`）が適用される。

## 本文の持ち方

本文は CRDT（Yjs）で保持され、Markdown はその射影。
レスポンスの `contentDocHash` が版を表し、更新時に `If-Match` ヘッダへ載せると楽観的並行制御が効く。
本文が無いノートは `contentMarkdown` に**空文字列**が返る（`null` にはならない）。

## 書き換えの単位（セクション操作）

全文を作り直さずに、**意図ベースの操作**で部分更新できる。

| 操作 | 何をするか |
|---|---|
| `replace_document` | 全文置換。既存本文があるときは `If-Match` が必須（本文の無い新規ノートへの最初の書き込みでは不要） |
| `append_section` | 末尾にブロックを追記 |
| `insert_section` | アンカーの前（`before`）または後（`after`）に挿入 |
| `replace_section` | アンカーが指すブロック範囲を置換 |
| `delete_section` | アンカーが指すブロック範囲を削除 |

位置は文字オフセットではなく**アンカー**で指す: `heading`（見出しテキスト。同名が複数あるときは
`occurrence` を 1 始まりで指定）/ `document_start` / `document_end`。
`block_id` は現状のスキーマにブロック ID 属性が無いため**未サポート（422）**。

既存ノートに書き足すときは、全文置換ではなくセクション操作を選ぶ。全文置換は人の同時編集を踏み潰す。
