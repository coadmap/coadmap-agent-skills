### 機能紐付け提案（`TaskProductFeatureLinkProposal`）

タスク・エピックに、どの機能を紐付けるかの提案。画面上の呼び名は
「Yataからの機能紐付け提案」「Yataによる機能紐付け判定」。

## 何か
- 対象はタスクまたはエピック。プロダクトヒエラルキー全体を見て候補を選ぶ。
- 判定が曖昧なときは確認対話になる。確認の質問と回答は、そのタスクのタイムラインに `purpose = PRODUCT_FEATURE_LINK` のセッションのトピックとして展開され、続きはタイムラインで行う（→ [セッション](L1.session.md)）。

## 候補から外れるもの

- **直前に却下された機能**は、階層上には残してユーザー判断として示すが、再選択しない。
- **既に紐付け済みの機能**も、階層上には示すが追加提案の選択肢からは除く。
- 対象タスクがそのプロダクトから外れていたら、提案は stale として扱う。

## 自動で走るとき

`role` が `SPRINT_BACKLOG` 以上（`DONE` を除く）のパイプラインへ動かしたとき、
機能が未紐付けなら自動で走る。プロジェクト設定
`WorkspaceSetting.autoTaskAttributeProposals.productFeature`（旧 `autoProductFeatureLinkProposalEnabled`）でオン／オフする。
オフにしても、ユーザーが明示的に依頼する提案は止まらない
（→ パイプラインの `role`）。

## タスク属性の提案の 1 つとして

機能の紐付けは、タスクの属性（機能・見積りなど）を Yata が候補から提案する「タスク属性の提案」の 1 つ（topic `pf_link`）。
新しい提案は決めること1件（`DecisionRecord`）として作られ、候補 1 つが変更案 1 つになる。
画面では、未決の件はタスク詳細の右サイドバーの一番上の「Yata の提案」欄に属性を問わず並び、そこで採用・やめる・他の候補を頼む・「合う機能がない」（新しい機能の案を頼む）。
紐付けの件の確認の問い（見出し「Yata が迷っています」）に文章で答える口は無く、機能を選ぶか「合う機能がない」で答える。
タイムラインには件ごとの履歴の行と確認の問いのトピックが残る（`TaskProductFeatureLinkProposal` はこの件を旧の形で読む互換の型）。
未決の件は MCP のタスク取得（`get_coadmap_task_dependency` の `openDecisions`）にも載り、
Claude Code などから `confirm_coadmap_task_decision` で確定できる（→ [タスクを閉じる前に](L5.task_close.md)）。
機能が決まるまで、同じタスクの目標の紐付けの提案（topic `objective_link`）は判断を待つ（機能が紐付けば、目標は機能の側で紐付けるため）。
