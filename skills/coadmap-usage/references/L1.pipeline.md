### パイプライン（`Pipeline`）

タスクの進行状態の列。プロジェクト（`Workspace`）ごとに**自由にカスタマイズ**される。

## 何か
- プロジェクトごとに自由に定義できるタスク状態の列。
- 名前はプロジェクトで自由に付けられる。
- タスクはパイプラインを移動しながら進行する。

## 標準のパイプライン構成

Coadmap がプロジェクト作成時に用意する標準構成:

| 名前 | 役割 | `role` |
|---|---|---|
| 新しいタスク | 新規タスクのデフォルト配置先（`is_default`） | `NONE` |
| 今週のタスク | スプリントバックログ相当 | `SPRINT_BACKLOG` |
| 今日やるタスク | | `FOR_TODAY` |
| 進行中のタスク | | `DOING` |
| レビュー中のタスク | | `IN_REVIEW` |
| 終了したタスク | クローズ用（`is_close`） | `DONE` |

各プロジェクトはこの標準構成をベースにカスタマイズして使う前提。名前は自由に変えられる。

**完了列（`is_close = true`）は必ず `role = DONE` を持つ**（BE のバリデーション
`close_pipeline_must_have_done_role`）。逆は成り立たず、`role = DONE` の列は
**1 つのプロジェクトに複数あってもよい**。「DONE の列＝完了列 1 本」と決めつけない。

`SPRINT_BACKLOG` は標準構成では「今週のタスク」に付く。プロジェクトによっては別の列に付け替えて使う。

## 名前と `role`

進行状態の意味は**基本的に名前で類推**する。
名前はプロジェクトごとにカスタマイズされる前提なので、そのプロジェクトの文脈で読む。

一部のパイプラインには **`role`**（GraphQL の enum `PipelineRole`）が付与される。
これは「このパイプラインは○○の意味を持つ」という補足のフラグで、**特定の自動挙動のトリガー**になる。
すべてのパイプラインに `role` が付くわけではない。

`role` の序列・自動挙動の一覧・各効果の細かい条件は
パイプラインの `role` にまとめてある。
`role` から挙動を判断するときは必ずそちらを見る。
