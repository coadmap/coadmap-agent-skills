### 監査ログ（`AuditEntry`）

誰が何をしたかの記録。画面上の呼び名は「監査ログ」。

## 何か
- タスクや機能のタイムラインとは**独立した専用の記録**。タイムラインの代わりではない。
- 1 件が `AuditEntry`。実行者・対象・操作・結果・発生源・時刻を持つ。

## 分類（`category`）

| 値 | 意味 |
|---|---|
| `RESOURCE_CHANGED` | ドメインリソースの変更（タイトル・担当・ラベル等） |
| `ORG_MEMBERSHIP` | 組織メンバー・招待・ロール変更 |
| `ACCESS` | アクセス制御（API キー / IAM） |
| `BILLING` | 課金・プラン変更 |
| `SYSTEM` | システム実行 |

## 結果と失敗理由

`outcome` は成功 / 失敗 / 認可拒否。失敗・拒否のときは `failureReason` に短い事由が入る。
**機微情報（パスワード・トークン・カード番号など）は格納しない**。

## null になりうるもの

- `actor` — ログイン失敗のような未認証アクセスでは `null`。試行された email 等は `metadata` に入る
- `sessionId` — 認証前のリクエストやサーバージョブ起因では `null`
- `requestId` — サーバージョブ起因（`source = SYSTEM`）では `null`

「実行者が空 ＝ 記録漏れ」ではない。未認証アクセスやシステム実行では正常に `null` になる。
