### タスク（`Task`）

作業の単位。担当・見積り・パイプライン・タイムラインを持つ、Coadmap の**最小実行単位**。

## 何か
- 「誰が・何を・どこまで」やる単位。
- プロジェクト（`Workspace`）内で、パイプラインを移動しながら進行する。

## 作成・更新時に指定できるフィールド

ここに挙げるのは **Yata と MCP ツールの経路で指定できるもの**。

| 種別 | フィールド | 備考 |
|---|---|---|
| 作成時必須 | `title` | タイトル |
| 作成時必須 | `namespace` | 所属ネームスペース |
| 作成時必須 | `workspaceId` | 配置するプロジェクト |
| 任意 | `pipelineId` | 配置するパイプライン。**省略可**で、省略するとプロジェクトのデフォルト pipeline に入る |
| 任意 | `description` | 本文（Markdown） |
| 任意 | `productFeatureIds` | 機能との紐付け（多対多） |
| 任意 | `objectiveLinkSubjectIds` | 目標・イニシアチブ・アウトカムとの直接の紐付け（多対多。3 種を混ぜてよく、種類はサーバが判定する。紐付けを許可していない種類・読めない ID は 422） |
| 任意 | `epicIds` | 親エピック（複数可、`Task.parentEpics`） |
| 任意 | `assigneeIds` | 担当者（アカウント、複数可） |
| 任意 | `labelIds` | ラベル（複数可） |
| 任意 | `sprintIds` | スプリント（複数可） |
| 任意 | `releaseIds` | リリース（複数可） |
| 任意 | `estimateValue` | 見積り（ストーリーポイント） |
| 任意 | `isHighPriority` | 優先度高フラグ |
| 任意 | `since` / `until` | 予定開始日・予定終了日。**ガントチャートに載る**（`WorkspaceGanttItem = Epic \| Objective \| Task`）ので、ユーザーが言っていない日付を推測で埋めない |
| **更新時のみ** | `predecessorTaskIds` / `successorTaskIds` | タスク依存（`TaskDependency`）。**作成時には指定できない** |

更新時、配列フィールドは**全置換**（渡した配列で置き換わる。追加ではない）。

GraphQL の `CreateTaskInput` には
`roadmapIds` / `connectedCraftIds` / `craftDiffScopeIds` / `assignAiAgents` / `knowledgeIds` /
`sourceIds` や作成時の依存指定もあるが、**Yata の経路からは指定できない**。
これらを前提にした案内をしない。

## エピックとの 2 系統の関係

- `Task.parentEpics`（複数）: そのタスクが属する**親エピック群**。`epicIds` で指定する。
- `Task.epic`（単数）: **タスク自身がエピック扱い**（`Task.isEpic = true`）の場合の対応エピック。`ConvertTaskToEpic` で生成される。

## 目標との関係

`Task.objectiveLinks` は、そのタスクが向かう目標・イニシアチブ・アウトカムを、次の 3 経路の和集合で返す（重複は除き、経路を `sources` に並べる）。

- `DIRECT`: タスク自身に `objectiveLinkSubjectIds` で紐付けたもの
- `PARENT_EPIC`: 親エピックに紐付いたもの（親エピックの親は辿らない）
- `PRODUCT_FEATURE`: 紐付いた機能の目標（目標だけ）

閲覧者が読めない目標系と、読めない親エピック・機能だけを通って繋がる目標系は返らない。紐付けを許可していない種類も返らない。
「このタスクは何のためか」を答えるときは 3 経路すべてを見る。

直接の紐付けの書き込みの規則:

- 紐付けられるのは、タスクのプロジェクトを持つ組織の目標系と、そのプロジェクトに紐付いた連携先の組織のプロダクトの下の目標系で、書き込む人が読めるものだけ。読めない ID・存在しない ID・許可していない種類・それ以外の組織の目標系は 422（黙って落ちない）。
- プロジェクトに属さないタスク（マイタスク）は直接の紐付けを持てない。
- 更新は全置換だが、置き換わるのは書き込む人が読めて許可されている種類の紐付けだけ。見えない紐付けは残る。
- エピックでないタスクでは、紐付けは権限・閲覧範囲を変えない。エピックであるタスクの紐付けはエピックの紐付けそのもので、目標の紐付けは権限の委譲に効く。目標の紐付けを変えるには、タスクの更新権限に加えて、書き込む前の状態のエピックの更新権限が要る（イニシアチブ・アウトカムだけなら要らない。→ [エピック](L1.epic.md)）。

## 進行状態と自動入力

- 進行状態は `workspacePipeline`（`Pipeline`）で表す。
- パイプラインの **`role`** によって特定の自動挙動がある（→ パイプラインの `role`）。
- `actual_started_at` は Pipeline 遷移時に自動入力（手動編集可）。
- `actual_finished_at` / `closed_at` は close 時に自動入力（手動編集可）。
- reopen 時は `closed_at` / `closed` / `actual_finished_at` がリセットされる。`actual_started_at` は保持される。
