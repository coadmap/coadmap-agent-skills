### セッション（`AiAgentSession`）

Yata とのやり取りの単位。画面上の呼び名は「セッション」。題名の無いセッションは「新しい会話」と表示される。

## 2 つの軸

**種別（`type`）** — 誰が始めたか。

- `CHAT`: ユーザーと Yata の対話
- `SMART`: Yata が能動的に提案・実行する側（ノート更新提案、スプリントレポート生成、
  リリースレポート生成、エピックからのタスク起票 等）

**目的（`purpose`）** — どの業務フローを担うか。種別と直交する。

- `GENERAL`: 特定の業務フローに紐づかない通常のセッション
- `REQUIREMENTS_REFINEMENT`: 要件整備（→ [要件整備](L1.requirements_refinement.md)）
- `ONBOARDING`: プロダクト・プロジェクト作成サポートの一括下書き生成
- `PRODUCT_FEATURE_LINK`: 機能紐付け提案の確認対話（→ [機能紐付け提案](L1.product_feature_link_proposal.md)）
- `CONSULT`: 外部の AI エージェントから MCP 経由で受けた相談。相談者だけが読める記録
- `MENTION`: タイムラインの @yata の会話。場所（タスク・ボードの対象）ごとに 1 つ。公開範囲は `INTERNAL` 固定で、作成者を持たない
- `MEETING`: 会議に Yata が同席するときの会話。同席ごとに 1 つ、同席を頼んだ人を作成者として作られる。公開範囲は `INTERNAL` 固定で、
  会議の回を読める人だけが読める（作成者も回を読めなくなったら読めない）

例: 要件整備のセッションは `type = CHAT`（人と往復する）かつ
`purpose = REQUIREMENTS_REFINEMENT`。**種別だけを見て「ただの雑談」と判断しない。**

## 一覧に出ないセッションがある

`PRODUCT_FEATURE_LINK` / `CONSULT` / `MENTION` / `MEETING` のセッションは、**ユーザーが自ら始めた会話ではないため Yata チャット一覧に出ない**。
`PRODUCT_FEATURE_LINK` と `MENTION` と `MEETING` はアーカイブも削除もできず、`CONSULT` と `MEETING` は画面から返信できない。
「チャット一覧に無い ＝ セッションが存在しない」ではない。

## 公開範囲（`accessibility`）

- `PRIVATE`: 作成者のみ（既定）
- `INTERNAL`: 組織メンバーに公開。ただしタスクや更新対象ノートに紐づく場合は、
  そのリソースの閲覧権限を持つメンバーに限定される
- `PUBLIC`: URL を知っていれば閲覧可

公開範囲を変更できるのは作成者だけ（`viewerCanUpdateAccessibility`）。ただし `MEETING` のセッションは作成者でも変更できない。
表の制限列（工数など閲覧権限が要る数値）の値を Yata が読んだ会話（`containsRestrictedValues`）は、
読む人が広がる変更（`PRIVATE` → `INTERNAL` / `PUBLIC`、`INTERNAL` → `PUBLIC`）を受け付けない。狭める変更はできる。

## タイムラインに載る

`REQUIREMENTS_REFINEMENT` と `PRODUCT_FEATURE_LINK` は、配下のメッセージが
タスクタイムラインへトピックとして展開される。返信はそのトピック宛に送る。
`MENTION` はトピックにならず、根のコメントの入れ子（`yataThread`）に出る。
