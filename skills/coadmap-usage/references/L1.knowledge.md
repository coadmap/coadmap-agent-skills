### ナレッジ（`YataKnowledge`）

サイドバーの「ナレッジ」。組織に蓄積される**再利用可能な知見**。GraphQL の `Knowledge`（学習カリキュラム）とは別物。

## 1 件の形

- `claim` — ナレッジ本文。**一文・断定形**で書く
- `why` — なぜそう言えるか
- `appliesTo` — 効く場面（部門・業務フェーズ等）
- `kind` — 知識の種類。`rule` / `lesson` / `context` / `document`。`document` はノートの「ナレッジとして参照させる」指定から生まれたもので、`claim` はノートの題名、本文は `noteUrl` のノート
- `category` — 旧い分類（判断 / 落とし穴 / 手続き）。非推奨。`kind=document` のときは null
- `form` — 型。`constraint`（制約：守るべき決まりごと）/ `precedent`（前例：実際に起きた特定の出来事）/ `procedure`（手順：複数のステップを順に踏む作業の流れ）/ `pointer`（指し先：判断や情報を持つ人・場所・文書の所在）。AI への渡し方はこの型で決まる。`kind=context` は型を持たない。既存のナレッジの型を判定し終えるまでは null のこともある
- `scope` — 適用範囲。**プロジェクト直属（`workspace`）か会社全体（`company`）**
- `lastSeenAt` — 最後に材料が観測された日時（鮮度の基準）

## 取得したときに何が返るか

チームナレッジの取得では、**人が採用を確定したものだけ**が返る。
候補・退役・却下・矛盾などの警告付きは含まれない。`lastSeenAt` の降順・**最大 50 件**。

「ナレッジが 0 件」は「組織に知見が無い」ではなく「**採用が確定したものが無い**」の意味。
候補段階のものを採用済みとして語らない。

## 提案

新しいナレッジは**提案として出す**（採用は人が決める）。
Yata が勝手に採用済みナレッジを増やすことはできない。

人はナレッジ画面の「ナレッジを追加」から、ナレッジを書いて直接足せる。
人が書いたものは提案を経ずに**採用済み**として入り、出典の種類は `manual`（書いた人と保存日時が付く）。

## タスク受け渡し時の同梱

タスクの詳細を取りに行くと、そのタスクに同梱されたナレッジが付いてくる。
同梱されるのは、**出し先にタスク受け渡し（`AGENT_TASK_HANDOFF`）を人が指定した、
採用済みかつ警告なしのもの**だけ。`displayId` は `KN-ORG-<n>` / `KN-PJ-<n>` の形で、
`claim` のほかに `why` / `body`（人が書き足した補足）/ `kind` / `form` / `noteUrl` が付く。
